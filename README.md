# 假设体检与追问（Assumption Exam and Grilling）提示词

## 简介

你是否也遇到过这种情况：明明已经用了"追问"（grill-me）这类提示词让 AI 反复盘问你的需求，结果它还是跑偏，生成的结果和你想要的南辕北辙？于是只能返工、重新沟通，白白消耗大量 token 和时间，心情也跟着变差。

问题出在哪？其实在 AI 开始追问你之前，它脑子里早就基于你没明说的地方，默默脑补了一堆假设————而这些假设你根本不知道。如果不先把这些假设摊开来看，AI 后续的追问方向就已经带偏了，因为它是在错误的假设基础上构建问题的。

解决方案很简单：在正式追问（grilling）之前，先加一轮"假设体检"——让 AI 把它脑子里那些你没有明说、但它已经默认成立的假设，逐条列出来给你看。你会发现，这些假设里有不少其实是错的。趁这个机会当场纠正，后面的追问就能顺着正确的方向展开，大大减少跑偏和返工的概率。

## 使用说明

无须安装skill，只须将下面的提示词复制粘贴，并插入到你的原始提示词（以“ABC”代表）之前，然后将这样拼接后的提示词发给你的Agent即可。

例如：

你的原始提示词: 

```
ABC
```

拼接后的提示词:

```
请在当前目录下，按下面要求完成任务：
1）在开始设计树之前，先执行 Round 0（假设体检）：
1.1) 列出我下面要求里没有明说、但你已默认成立的假设（逐条编号，形如：A1、A2、A3……）；
1.2) 列出你还缺哪些关键信息，并说明每条信息会如何改变你的方案（逐条编号，形如：M1、M2、M3……）；
1.3) 指出人们处理这类问题时最常犯的一个错误；
1.4) 只提一个最关键的问题 —— 这个问题要能帮你搞清我的真实目标和具体处境，而不是最后给我一份谁都能套用的通用建议。这个问题的格式如下：
[```
❓ **Q0** - **<问题标题>**: <问题正文，可能包含多个段落及选项>

➡️ <您的建议答案>
```]
2）Round 0 只问上述这一个问题，不要提前问别的。我回答后，你再按 追问 的常规轮次（frontier / 编号问题 / 推荐答案）推进设计树，直到前沿清空。
3）按下面追问的要求盘问我的诉求：
---
名称: 追问
描述: 针对某项计划、决策或想法，对用户进行深入且严密的追问。适用于用户希望压力测试其思路，或使用了任何触发“拷问”模式的关键词句时。
---

对用户进行持续、深入的追问，直到双方达成共识。将此过程构建为一棵**决策树**：每一项决策都会衍生出后续相关的决策分支。

按**轮次**推进这棵树的构建。**前沿（frontier）**指的是那些前提条件已确定的决策——即您可以**立即**提问、而无需猜测尚未获知答案的问题。在每一轮中，提出“前沿”上的所有问题：为每个问题编号并给出您的建议答案。随后等待用户回答，再进入下一轮。

每个问题的格式应如下所示：

[```
❓ **Q1** - **<问题标题>**: <问题正文，可能包含多个段落及选项>

➡️ <您的建议答案>
```]

用户在每一轮的回答都会重塑决策树：已确定的决策会将“前沿”向外推进，并解锁那些依赖于这些决策的问题。重新计算“前沿”并进行下一轮提问。如果某个问题的答案依赖于本轮中尚未确定的另一个问题，则该问题应归入**后续**轮次，而非当前轮次。

发掘**事实**是您的职责，绝非用户的职责。当“前沿”上的某个问题需要获取环境（如文件系统、工具等）中的事实信息时，应指派子代理（sub-agent）去查找；切勿向用户询问您自己就能查到的信息。不要因此停滞不前：正在进行的探索属于尚未确定的前提条件，因此只有依赖于该探索结果的后续问题才需要等待子代理的报告；您可以立即提出“前沿”上的其他问题。**决策**权在于用户：将每一项决策提交给用户，并等待其回应。
4）我的诉求如下：

ABC
```
